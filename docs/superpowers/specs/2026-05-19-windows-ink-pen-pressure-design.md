# Windows Ink 数位板实时压感映射设计文档

## 1. 目标

为当前桌面程序增加第一版数位板支持，限定为 `Windows Ink / Windows 原生数位板输入链路`。用户在系统范围内使用支持 Windows Ink 的数位板时，程序需要持续采集笔尖接触和压感变化，并把压感实时映射为 EMS 输出强度，而不是仅触发固定波形。

本次目标强调“跟手感”：

- 落笔即开始输出
- 压得越重，输出越强
- 压感变化能够实时反映到输出强度
- 抬笔即停止输出

## 2. 范围

本次包含：

- 支持 Windows Ink 原生输入链路设备
- 支持笔尖接触事件
- 支持压感 `pressure` 实时采样
- 支持把压感映射为连续强度输出
- 支持抬笔时立即停止输出
- 支持压感不可用时回退为“触发固定波形”

本次不包含：

- WinTab 驱动兼容
- 悬停、橡皮擦、倾角、旋转等高级笔数据
- 数位板按钮自定义动作
- 用户可视化配置压感曲线编辑器
- 多设备压感校准配置

## 3. 核心方案

采用“通用输入事件模型 + Windows Ink 笔输入后端 + 实时强度输出通道”的方式实现。

整体思路：

1. 将当前“全局键盘监听”模型升级为“全局输入监听”模型
2. 键盘和数位板统一发出输入事件，但保留各自的来源信息
3. 数位板事件不走“固定波形规则命中”链路，而是走独立的“实时强度输出”链路
4. 当设备无法提供可靠压感时，回退为触发用户预设波形，保证功能可用

## 4. 总体架构

### 4.1 输入层

新增通用输入抽象，替代当前仅面向键盘的：

- `IGlobalKeyboardListener`
- `KeystrokeCapturedEventArgs`

建议演进为：

- `IGlobalInputListener`
- `GlobalInputEventArgs`
- `InputSourceType`

其中：

- 键盘后端继续复用当前全局键盘钩子
- 数位板后端新增 Windows Ink 输入桥接

### 4.2 数位板输入后端

新增 Windows 原生笔输入适配层，职责包括：

- 订阅全局笔尖接触生命周期
- 采样压感值
- 对压感做归一化和节流
- 把笔输入转换为统一事件模型

第一版只识别：

- `PenDown`
- `PenMove`
- `PenUp`

### 4.3 运行控制层

`AppBootstrapper` 继续作为运行时协调中心，但要拆出两条输入处理链路：

- 键盘链路：继续进入测速、规则、空闲提醒
- 数位板链路：进入压感映射与实时强度输出

这样可以避免把“压感输出”硬塞进“波形规则”模型，减少行为耦合。

### 4.4 设备输出层

在现有 BLE 设备管理能力之上，增加一条“实时强度输出”能力：

- 设置当前 A/B 通道强度
- 节流更新输出
- 抬笔发送停止指令

这条链路与“播放预设波形”并行存在，不替代现有波形系统。

## 5. 统一输入事件模型

建议新增统一事件字段：

- `SourceType`
  - `Keyboard`
  - `Pen`
- `Timestamp`
- `Phase`
  - `Down`
  - `Move`
  - `Up`
- `Pressure`
  - `0.0 ~ 1.0`
- `VirtualKey`
  - 仅键盘事件使用
- `DeviceId`
  - 可选，后续用于调试和扩展

设计原则：

- 键盘事件保留原能力
- 数位板事件不伪装成键盘事件
- 运行时逻辑通过 `SourceType` 分流

## 6. 压感映射策略

第一版不建议直接把 `pressure` 线性乘以最大强度。为了体验更稳定，需要加入三个处理阶段：

### 6.1 死区

轻微接触和硬件抖动不应立即出力。

建议：

- `pressure < 0.08` 视为 `0`

### 6.2 有效区间归一化

将有效压感区间重新映射到 `0.0 ~ 1.0`。

示意：

- 原始 `0.08 ~ 1.00`
- 归一化后 `0.0 ~ 1.0`

### 6.3 输出强度映射

建议将归一化压感映射到较实用的强度区间，而不是从 0 开始。

建议第一版默认区间：

- `A/B 18 ~ 62`

这样轻压也能感知，重压也不会过猛。

### 6.4 平滑与节流

为避免发包过密和强度抖动：

- 仅在强度变化达到阈值时发送更新
- 更新节流间隔控制在 `40 ~ 60ms`
- 相邻两次强度变化过小则忽略

## 7. 输出行为

### 7.1 落笔

当检测到 `PenDown`：

- 读取当前压感
- 计算目标强度
- 若强度大于 0，则立即开始输出

### 7.2 落笔移动

当检测到 `PenMove`：

- 按节流频率更新目标强度
- 若仍在有效压感区间，则继续更新输出
- 若降到死区以下，视为暂时无效强度，可停止输出或等待下一次有效压力恢复

### 7.3 抬笔

当检测到 `PenUp`：

- 立即发送停止指令
- 清空当前实时压感状态

## 8. 回退策略

第一版必须考虑某些设备虽然走 Windows Ink，但无法稳定提供可用压感的场景。

回退策略如下：

- 若笔输入存在，但压感字段缺失或长期恒为 0
- 或压感采样无法通过最小稳定性校验

则切换为回退模式：

- `PenDown` 触发一条预设波形
- `PenUp` 发送停止指令

该回退模式只作为兼容兜底，不作为默认主路径。

## 9. 与现有功能的关系

### 9.1 键盘功能

以下行为保持不变：

- 按键即触发
- 键速规则触发
- 空闲超时提醒

### 9.2 数位板功能

第一版建议作为独立输入能力接入，不影响现有键盘规则模型。

换句话说：

- 键盘继续驱动速度统计与规则系统
- 数位板优先驱动实时强度输出系统

后续如果需要“键盘和数位板统一映射到同一规则系统”，再在第二阶段扩展。

## 10. 错误处理与诊断

至少需要覆盖以下诊断信息：

- 是否检测到 Windows Ink 笔输入后端
- 是否收到 `PenDown / PenMove / PenUp`
- 原始压感值与归一化压感值
- 最近一次下发的目标强度
- 是否进入回退固定波形模式

错误处理原则：

- 数位板初始化失败不影响原有键盘功能
- 压感数据异常时自动回退，不导致程序崩溃
- 设备输出失败只记录日志并停止当前实时输出

## 11. 测试策略

至少覆盖以下测试：

### 11.1 单元测试

- 压感死区过滤
- 压感归一化
- 压感到强度的映射
- 节流逻辑
- 回退条件判断

### 11.2 协调层测试

- `PenDown` 会启动实时输出
- `PenMove` 会更新强度
- `PenUp` 会停止输出
- 数位板异常不会破坏键盘链路

### 11.3 手工验证

- 轻压、中压、重压体验差异明显
- 快速提笔时立即停止
- 长时间按压不会发包失控
- 无压感设备可正确回退到固定波形

## 13. 建议实施顺序

1. 先抽通用输入事件模型
2. 保持键盘链路可用并通过回归测试
3. 接入 Windows Ink 笔输入后端
4. 加入压感映射和实时强度输出
5. 增加回退固定波形逻辑
6. 完成诊断日志和手工验证
