# 键盘打字速度蓝牙联动程序设计文档

## 1. 目标

构建一个仅支持 Windows 桌面端的独立程序，用于全局监听系统键盘输入，实时计算打字速度，并按速度区间自动触发蓝牙 EMS 设备波形。程序需要提供现代化桌面界面，覆盖蓝牙接入、设备控制、自定义波形、波形图展示、自定义速度区间事件，以及波形绑定事件等完整能力。

## 2. 约束与前提

- 项目目录为 `D:\keybord-link-yokonex`
- 当前目录为空目录，需要新建独立项目
- 平台限定为 Windows 桌面端
- 目标蓝牙设备与 `D:\STS2-Link-YOKONEX` 当前支持的 EMS 设备同类
- 蓝牙接入、波形模型、发包协议、规则绑定思路尽量参考 `D:\STS2-Link-YOKONEX`
- 打字速度统计范围为系统全局键盘输入，不局限于程序窗口内
- 自定义事件按速度区间触发，不做复杂表达式规则作为第一阶段目标

## 3. 技术选型

### 3.1 推荐方案

- 语言：`C#`
- 框架：`.NET 9`
- UI：`WPF`
- 蓝牙：Windows 原生 BLE API
  - `Windows.Devices.Bluetooth`
  - `Windows.Devices.Bluetooth.GenericAttributeProfile`
  - `Windows.Devices.Enumeration`
- 配置持久化：`System.Text.Json`
- 图表与波形绘制：优先自绘轻量控件，必要时引入轻量图表库

### 3.2 选型理由

- 与参考项目 `STS2-Link-YOKONEX` 的语言和平台一致，便于复用现有 BLE、波形、规则模型设计
- Windows 下全局键盘钩子与 BLE 都更适合使用 .NET 原生能力完成
- WPF 在桌面工具型应用中成熟稳定，适合快速实现现代化布局、图表和编辑器
- 第一阶段不追求跨平台，优先保证 BLE 接入稳定性、输入监听可靠性和设备控制精度

## 4. 总体架构

程序拆分为以下模块：

### 4.1 `KeyboardSpeed.Desktop`

WPF 桌面壳，负责：

- 主窗口
- 导航与页面切换
- 实时状态卡片
- 设备连接界面
- 波形编辑器
- 波形图预览
- 速度区间规则编辑

### 4.2 `KeyboardSpeed.Core`

纯业务层，不依赖 UI 和 Windows API，负责：

- 打字速度统计模型
- 速度区间规则模型
- 波形定义模型
- 规则匹配与冷却判断
- 配置模型与配置序列化

### 4.3 `KeyboardSpeed.Bluetooth.Windows`

Windows BLE 适配层，设计方式参考 `STS2-Link-YOKONEX` 中的：

- `WindowsBlePlatformBridge`
- `WindowsBleDeviceManager`
- `EmsBleProtocolAdapter`
- `BluetoothTelemetryStore`

职责包括：

- 扫描设备
- 连接与断开
- 设备状态刷新
- 波形发包
- 设备通知解析

### 4.4 `KeyboardSpeed.Input.Windows`

系统全局键盘监听层，负责：

- 安装低级键盘钩子
- 采集按键时间戳
- 过滤无效键与修饰键
- 对外输出按键事件流

### 4.5 `KeyboardSpeed.Tests`

测试项目，覆盖：

- 打字速度计算
- 区间命中逻辑
- 冷却时间判断
- 波形绑定逻辑
- 配置序列化
- 协议发包转换

## 5. 运行时数据流

整体运行时数据流如下：

1. 全局键盘监听模块接收系统按键输入
2. 速度统计器基于滑动窗口更新实时速度
3. 规则引擎匹配当前速度命中的区间规则
4. 规则执行器决定是否切换或停止当前波形
5. 蓝牙设备管理器将目标波形转换为协议包并发送
6. UI 层同步展示当前速度、当前命中规则、当前波形和设备状态

## 6. 打字速度模型

### 6.1 速度指标

程序同时计算两类指标：

- `KPM`：每分钟击键数，作为主指标
- `WPM`：折算后的每分钟单词数，作为辅助显示

### 6.2 计数规则

默认计入以下按键：

- 字母
- 数字
- 常用符号
- 空格
- 回车
- 退格

默认不计入以下按键：

- `Ctrl`
- `Alt`
- `Shift`
- `Win`
- 其他单独按下的修饰键

### 6.3 统计窗口

建议保留两个时间窗口：

- `10 秒实时窗口`
  - 用于规则触发
  - 响应快
- `30 秒趋势窗口`
  - 用于趋势图展示
  - 曲线更平滑

### 6.4 稳定性策略

- 使用滑动窗口而非简单总量累加
- 在边界抖动场景下，规则执行由冷却策略约束
- 键盘事件采集与 UI 更新分离，避免界面阻塞影响测速

## 7. 速度区间事件模型

### 7.1 第一阶段规则形态

第一阶段仅支持按速度区间触发规则。

每条规则包含：

- 规则 ID
- 规则名称
- 是否启用
- 指标类型：`KPM` 或 `WPM`
- 最小值
- 最大值
- 目标波形 ID
- 冷却时间（毫秒）
- 进入区间是否立即触发
- 区间内是否允许重复触发
- 离开区间时是否发送停止波形

### 7.2 典型示例

- `低速区`：`0-120 KPM -> 柔和波形`
- `中速区`：`121-220 KPM -> 节奏波形`
- `高速区`：`221-999 KPM -> 强刺激波形`

### 7.3 执行策略

为避免边界抖动频繁切换，第一阶段必须支持：

- 规则冷却时间
- 当前激活规则记忆
- 区间变化时才切换波形

## 8. 波形系统设计

### 8.1 波形定义

波形设计尽量贴近参考项目的 `EmsWaveformDefinition` 和 `EmsWaveformStep`。

每个波形包含：

- `Id`
- `Name`
- `ExecutionMode`
- `LoopCount`
- `Steps`

### 8.2 波形步骤

每个 `step` 包含：

- `DurationMs`
- `AStrength`
- `AMode`
- `BStrength`
- `BMode`
- `MotorState`

### 8.3 第一阶段波形能力

- 新增波形
- 复制波形
- 删除波形
- 编辑波形步骤
- 调整步骤顺序
- 试播波形
- 停止波形
- 从内置预设复制为自定义波形

### 8.4 默认内置波形

第一阶段建议提供若干现代化命名的预设波形，例如：

- `Soft Pulse`
- `Focus Tap`
- `Heartbeat`
- `Sprint Burst`

## 9. 蓝牙接入设计

### 9.1 设计原则

蓝牙接入方式参考 `D:\STS2-Link-YOKONEX`，沿用以下分层思路：

- 设备管理器：面向应用层的统一控制入口
- 平台桥接：封装 Windows BLE 细节
- 协议适配器：负责 EMS 波形转发包
- 遥测存储：保存最近状态样本

### 9.2 第一阶段蓝牙能力

- 扫描同类 EMS 设备
- 连接设备
- 断开设备
- 刷新设备状态
- 下发自定义波形
- 执行停止命令
- 展示设备电量和基础连接状态

### 9.3 第一阶段暂不支持

- 多设备同时联动
- 云同步
- 非同类协议适配
- 复杂多规则并行动作编排

## 10. 界面设计

### 10.1 设计目标

界面需要现代化、清晰、可读性高，不采用传统工具面板式堆叠布局。

### 10.2 风格原则

- 中性现代配色
- 大卡片布局
- 圆角容器
- 柔和阴影与分层
- 高对比指标数字
- 简洁编辑区
- 图表与波形可视化优先

### 10.3 页面结构

主窗口建议包含 4 个主页面：

#### 概览

- 当前蓝牙连接状态卡片
- 当前实时 `KPM / WPM`
- 当前命中速度区间
- 当前执行波形
- 最近 30 秒速度趋势图
- 扫描、连接、停止等快捷操作

#### 设备

- 扫描到的设备列表
- 设备名称
- 设备类型
- 电量
- 连接状态
- 连接 / 断开 / 刷新按钮

#### 波形库

- 波形列表
- 波形编辑器
- 波形步骤列表
- 波形预览图
- 新增 / 复制 / 删除 / 导入预设 / 立即试播

#### 事件绑定

- 速度区间规则列表
- 区间范围编辑器
- 波形绑定下拉框
- 冷却时间设置
- 离开区间行为设置

## 12. 测试策略

### 12.1 单元测试

重点覆盖：

- KPM/WPM 计算
- 滑动窗口统计
- 区间命中判断
- 冷却时间判断
- 波形绑定逻辑
- 配置序列化与反序列化

### 12.2 协议层测试

重点覆盖：

- 波形步骤转协议包
- 停止包生成
- 强度、时长等边界值裁剪

### 12.3 手工联调清单

- 全局键盘监听是否稳定
- 切换到其他应用后测速是否仍有效
- 蓝牙设备扫描连接是否稳定
- 波形试播是否生效
- 速度跨区间时是否正确切换波形
- 设备断开后是否能安全停止
